## Part A — Design principles & strategy

1. **One region config, consumed everywhere.** Today the "place" is hard-coded in ~30 files (Bengaluru coords `12.9716, 77.5946`, Mangaluru strings, faker-random cities). All of it funnels through two new files:
   - Backend: `backend/app/core/region.py` (or `app/services/region.py`) — one module exporting `REGION`, `CITY`, `CENTER`, `BOUNDS`, `AREAS`, `TALUKS`, `ROADS`, `LANDMARKS`, `PINCODES`, `RTO_CODE`, `HOSPITALS`, `GOV_BODIES`, `AMBULANCE_BASES`, etc.
   - Frontend: `client/src/config/region.js` — the mirror for map defaults, labels, fallbacks.
   Nothing else should contain a raw coordinate or city name after the migration (exceptions: none).

2. **No database-schema changes.** LifeLink stores everything as flexible `Document` rows (Mongo-style shapes in Postgres JSONB). We only change **what gets seeded** and **default fallbacks**. A fresh DB re-seed produces a fully Hassan-consistent world.

3. **Fresh-seed strategy, not in-place migration.** The demo world (100×4 users, hospitals, ambulances, incidents) is generated by `backend/scripts/seed_mass_demo_data.py` + `bootstrap_database.py` on first boot. We edit the generators, then wipe volumes (`docker compose down -v`) so the new world seeds cleanly. A tiny one-time migration script is included only to normalize the **mixed location shapes** already documented in Part B (string vs object) — this bug exists today and must be fixed for `Find Hospital` / `nearby` to work correctly in Hassan.

4. **Real institutions, honest confidence levels.** Part C lists real Hassan institutions. Items marked **[V]** are well-established and safe to ship; items marked **[P]** are plausible placeholders that must be name-validated (Google Maps / Hassan district health office listing) before a public demo. The seed script reads from these lists, so swapping a placeholder for the correct name later is a one-line edit.

5. **Government portal = district ecosystem.** The current gov portal models 62 national organizations (NDMA, ministries…). For Hassan we replace the UI catalog with the **Hassan district emergency & health ecosystem** (Part C.5) while reusing the existing backend org/auth machinery (keys, sub-roles `district_admin/district_officer/...` already exist in `GOV_SUBROLES`). National orgs stay in the backend registry (harmless, hidden in UI) so nothing breaks.

6. **Geolocation default = Hassan.** `FindHospitalScreen` uses `navigator.geolocation`; when the user denies/shares from outside Hassan, the app must fall back to Hassan center instead of a blank map. Every map default becomes `REGION.center`.

7. **Config flag for reversibility.** `APP_REGION` env var (backend) / `VITE_APP_REGION` (client) defaults to `hassan`. Keeping the mechanism generic costs nothing and lets the same repo be re-pointed at another district later without a rewrite.

### B.6 Cross-cutting bug (must fix for Hassan to display correctly)
Two different `location` shapes exist in the `hospitals` collection:
- `seed_mass_demo_data.py` → `location: "Hassan"` (string)
- `v2/hospital.py::_seed_hospitals` → `location: {lat, lng, address, city, state}` (object)
- `hospital_ops_shared.py` reads `doc.get("location") or {...}` expecting an **object**; `FindHospitalScreen` relies on `/v2/hospital/nearby` which reads lat/lng from the object.

**Decision:** standardize on the **object** shape `{lat, lng, address, city, district, state, pincode}` everywhere + add `scripts/migrate_hassan_locations.py` to upgrade any string location during the transition (Part J). New seeds write objects only.

## Part E — Phase 1: `indian_locale.py` localization

`backend/app/services/indian_locale.py` becomes Hassan-first (it is the shared table every seeder already imports):

1. `DEFAULT_CENTER_LAT/LNG` → Hassan `13.0068 / 76.0996`; `PRIMARY_CITY = "Hassan"`.
2. Add `HASSAN_AREAS`, `HASSAN_ROADS`, `HASSAN_PINCODES`, `TALUKS` (from C.2–C.4) and have `random_address(city=None)` draw areas + pincodes from Hassan tables and build `"…, <area>, Hassan, Karnataka – 5732xx"`.
3. `SECONDARY_CITIES` → the **8 taluk HQ names** + catchment district HQs (Chikkamagaluru, Madikeri, Mandya, Mysuru, Tumakuru) — used only for "nearby district" flavor, never for primary seeds.
4. `DISTRICTS` → `["Hassan", "Chikkamagaluru", "Kodagu", "Mandya", "Mysuru", "Tumakuru"]`.
